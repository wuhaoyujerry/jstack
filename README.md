# jstack

Jerry's dev workflow: size, idea, recipe, saute, taste, review. Each has a file in `skills/cooking/phases/`.

- Generic workflow: `skills/cooking/SKILL.md`, `skills/cooking/models.md`, `skills/cooking/meal.md`, and `skills/cooking/phases/`.
- `skills/idea/` is the idea phase as its own skill; `phases/idea.md` points to it. `skills/research/` is a separate skill that idea and recipe call for a missing fact. `skills/improve/` is a separate skill, typed as `/improve`, that turns the observations of the review phase into workflow changes. It runs in this repo: typed in another repo, it hands the ask to a session here, and it hands a change to another repo's file to a session there. `/idea <topic>` is typed only; `research` also starts when a prompt says research, or asks how code works, why it has its shape, what a tool does, or which option to pick.
- Private work rules: `overlays/work.md`. An overlay's `## Hooks` section attaches other skills after a phase, for example `- after taste: <absolute path to SKILL.md>. <note>`. The whole `overlays/` directory is Git-ignored and outside the synced skill. It also holds `tasks.txt`, the map from the ids in the logs to this machine's dish folders.
- Shared logs: `logs/sizing-log.md` and `logs/review-log.md`. `logs/` is a clone of the private repo `jstack-logs`, Git-ignored here; on a new machine run `git clone git@github.com:wuhaoyujerry/jstack-logs.git logs` in this checkout. Review pushes its lines there with `skills/cooking/logs.sh`, and `/improve` reads the lines of every machine. A line names its repo and dish by id and holds no project detail; the script stops a push whose lines name a repo, its owner or a home path. Review saves a fact about the project itself, as a page of that project's memory through the `ai-memory` CLI, and that line reads `applied`; every other line waits for `/improve`. A session prints those saved facts before it works on a dish. `tests/logs.sh` tests the script.
- `skills/cooking/scope.sh` is the scope check that saute runs before the commit of each unit: it lists the files the unit changed and counts its added tests against the cases its check lists. `tests/scope.sh` tests the script.
- The skill resolves its real directory before finding `../../overlays/` and `../../logs/`. Overlays are optional and are not distributed to other machines.
- A **dish** is one piece of work that cooking runs. Its files stay in the working repo's **cookbook**: the Git-ignored `.cookbook/` directory, one folder per dish under `dishes/`. A **meal** is one goal cooked as several dishes: its folder `meals/<meal>/` holds `meal.md`, which lists them, and the folder of each.
- The cookbook is in the main checkout, and every worktree of the repo shares it. Cooking sizes a dish and runs its idea phase in the main checkout, then **hands it off**: Orca creates a worktree for the dish and starts a Pi agent there, which cooks the rest. A meal is handed off whole to a **meal agent** in the meal worktree. It starts each dish as an Orca worker in a child worktree, shows you each dish's gates and reports, merges a finished dish into the meal branch, and then starts the dishes that waited for it.
- Link a checkout: `skillshare link "$PWD/skills/cooking" --name cooking --enable -g`, the same for `skills/idea`, `skills/research` and `skills/improve` under their own names, then `skillshare sync -g`.
- `skills/technical-writing/` and `skills/unslop/` are copies of pstack skills (MIT). `idea` reads them by path to write the brief; they need no link.
- `skills/idea/gate-page.sh` builds the **gate page**: the page that idea shows at the brief gate, with the goal, one picture of the change and the brief's lines for the user. It renders the page with [answer-me-with-html](https://github.com/QingYunA/answer-me-with-html), which needs Node.js 20 or later. It finds the tool in `~/.agents/skills/` or `~/.claude/skills/`; `IDEA_PAGE_TOOL` names another `am.mjs`. Without the tool, idea shows the text summary. `tests/gate-page.sh` tests the script and spends no model tokens.
- Skillshare and agent skill folders link here; edits through those links change this repo.
- `SOURCES.md` records the origins of each phase.
- `SCENARIOS.md` lists behaviours that must hold; `/improve` checks each skill change against it, then proves the change with behaviour cases.
- `tests/behaviour/run.sh` runs scenarios as headless Pi agents on seeded fixtures and asserts on the files they leave. It runs each case three times on both main-agent models and spends model tokens. On a machine with another provider name or another main-agent model, `overlays/model-map.txt` maps it, one `<provider or id> <replacement>` per line, and the runner applies the map to its default ids; `tests/behaviour/run.sh <case>` runs one. A case is a folder in `tests/behaviour/cases/` with `setup.sh`, `prompt.txt` and `assert.sh`. A `cwd` file starts the agent in that path under the run directory. An `orca-worktrees` file makes the Orca stub create the worktrees it is asked for, and an `orca-inbox` file holds the mail that the agent's first `check` reads. A stub takes the place of `ai-memory` and keeps each page in the run directory. The agent starts in the fixture repo; a case whose prompt names the improve skill starts in the skills copy, unless it has a `from-repo` file. A symbolic link to a case folder is an alias: the id of a second scenario that the case asserts too. It runs by name, and a run of every case skips it. A fixture that several cases share and no case owns is a script in `tests/behaviour/fixtures/`, which a `setup.sh` sources.
- `skills/writing-for-agents/` is a copy of Matt Pocock's skill (MIT), without its Codex-only `agents/` folder; `SOURCES.md` records it, and `/improve` checks it for upstream changes. `AGENTS.md` requires it before edits to `skills/`.
- Invoke: `/cooking <ask>`. An ask to continue a dish resumes it from its ledger. An ask that names a meal resumes its next dish. An ask that reports what happened to a finished dish adds it to the review log, and an issue to fix reopens the dish at saute.
